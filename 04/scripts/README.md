## The three levels of digital certification (§4.2.2)

The chapter describes three levels of metadata and certification for digital artworks. The scripts and the demo model in `models/` demonstrate all three together:

```
Level 1 — Internal / Informal
  blender_metadata.py → writes Custom Properties inside the .blend file
  (author, title, date, license, version, notes)
  Visible in: Properties panel → Scene → Custom Properties
  Fragile: editable by anyone, not standardised, not verifiable externally.

Level 2 — External / Certified
  certify_asset.py → computes SHA-256 hash → writes .cdm.json
  The hash is a unique fingerprint of the file's exact content.
  If even one byte changes, the hash changes completely.
  Verifiable by anyone with Python, no account or platform needed.

Level 3 — On-chain / Permanent (optional)
  ots stamp <file>.cdm.json → anchors the hash to the Bitcoin blockchain
  Provides a decentralised, tamper-proof timestamp.
  No NFT or blockchain account required (OpenTimestamps is free).
```

### See it in action — the demo model

Open `models/metadata_demo.blend`. Go to **Properties panel → Scene → Custom Properties**: the Level 1 metadata block is already there.

Alongside it, `models/metadata_demo.blend.cdm.json` is the Level 2 certificate — the SHA-256 fingerprint generated by `certify_asset.py` at the time of creation.

To verify the file has not changed since certification:

```bash
python certify_asset.py ../models/metadata_demo.blend --verify
# → [OK] Hash matches — file is unaltered since certification.
```

To certify your own file for the first time:

```bash
python certify_asset.py my_artwork.blend --author "Your Name" --notes "Version 1.0"
# → my_artwork.blend.cdm.json  (keep this alongside the artwork)
```

To certify a new version and chain it to the previous certificate:

```bash
python certify_asset.py my_artwork_v2.blend \
  --author "Your Name" \
  --notes "Texturing complete" \
  --previous my_artwork.blend.cdm.json
# → my_artwork_v2.blend.cdm.json  (contains previous_hash linking back to v1)
```

## How to certify your own Blender files

Three ways, from quickest to most flexible.

### Option A — Drag and drop (Windows, no terminal)

Drag your `.blend` file onto `run_certify_asset.bat`.  
The `.cdm.json` certificate is created automatically next to your file. Done.

### Option B — From the terminal

```bash
python certify_asset.py C:\path\to\your\file.blend \
  --author "Gianpiero Moioli" \
  --notes "Final version"
# → your_file.blend.cdm.json
```

### Option C — Full workflow for a new artwork

```bash
# Step 1 — in Blender
#   Open your .blend → Scripting workspace → open blender_metadata.py
#   Edit the CONFIG block (title, date, license…) → Alt+P → save the file

# Step 2 — certify the saved file
python certify_asset.py artwork.blend \
  --author "Gianpiero Moioli" \
  --notes "First certified version"
# → artwork.blend.cdm.json  ✓

# Step 3 — keep the .cdm.json ALWAYS next to the .blend
#   They are inseparable: the JSON contains the fingerprint of that exact file.

# Step 4 — verify at any time
python certify_asset.py artwork.blend --verify
# → [OK] Hash matches — file is unaltered since certification.
# → [FAIL] Hash mismatch — file has been modified.

# Step 5 (optional) — anchor to Bitcoin blockchain, free
pip install opentimestamps-client
ots stamp artwork.blend.cdm.json
# → artwork.blend.cdm.json.ots   ← blockchain proof, keep this too
```

### When you save a new version

Always re-certify and chain to the previous certificate:

```bash
python certify_asset.py artwork_v2.blend \
  --author "Gianpiero Moioli" \
  --notes "Texturing complete" \
  --previous artwork.blend.cdm.json
# → artwork_v2.blend.cdm.json
#   (contains previous_hash → tamper-evident chain across all versions)
```

> **Key rule:** if you modify and re-save the `.blend`, the old `.cdm.json` no longer matches. Always re-certify after every saved version you want to officially record.

## `aura_transition.py` — Aura & Reproducibility Diagram

**§4.1 · Reference diagram**

Generates the conceptual diagram of the chapter as a standalone SVG — two crossing curves (**Aura** and **Reproducibility**) across five historical phases of art production, from the handmade object to AI-generated work. Plots Walter Benjamin's argument (*Das Kunstwerk im Zeitalter seiner technischen Reproduzierbarkeit*, 1935) and extends it through the digital and generative AI era.

**Run:**
```bash
python aura_transition.py                        # saves SVG in current folder
python aura_transition.py --output path/folder   # custom output folder
```

### The five phases

| Phase | Period | Aura | Reproducibility |
|-------|--------|------|-----------------|
| Handmade Object | pre-1800 | 1.00 | 0.00 |
| Cast / Mould | 1800–1880 | 0.75 | 0.22 |
| Mechanical Reproduction | 1880–1960 | 0.30 | 0.70 |
| Digital / Parametric | 1960–2020 | 0.20 | 0.95 |
| AI-Generated | 2020 onwards | 0.55 | 1.00 |

> Note the "generative aura" paradox: at the AI-Generated phase, reproducibility reaches its maximum while aura partially recovers — because each generation is a unique, unrepeatable process.

### Parameters (edit inside the script)

| Variable | Default | Description |
|----------|---------|-------------|
| `PHASES` | 5 entries | Each entry: `label`, `year`, `aura`, `repro`, `color`, `note` |
| `W`, `H` | `900`, `480` | SVG canvas size in pixels |
| `PAD_L/R/T/B` | `60/30/70/110` | Chart margins |

## `certify_asset.py` — Certified Digital Manifest Generator

**§4.3.4 · Appendix A**

Computes a SHA-256 fingerprint for any digital file and writes a **Certified Digital Manifest** (`.cdm.json`) alongside it. CDMs can be chained across versions to create a tamper-evident audit trail.

**Run:**
```bash
# Certify a file
python certify_asset.py artwork.blend
python certify_asset.py artwork.blend --author "Your Name" --tool "Blender 5.x" --notes "Final version"

# Chain to a previous certificate (new version audit trail)
python certify_asset.py artwork_v2.blend --previous artwork.blend.cdm.json

# Verify — check the file has not changed since certification
python certify_asset.py artwork.blend --verify

# Windows launcher (drag any file onto it)
run_certify_asset.bat
```

### CDM format

```json
{
  "id_version":    "CDM-1.0",
  "file_name":     "artwork.blend",
  "sha256_hash":   "c0f3b85d...",
  "timestamp_utc": "2025-01-01T12:00:00Z",
  "author":        "Gianpiero Moioli",
  "tool":          "Blender 5.x + certify_asset.py",
  "previous_hash": null,
  "notes":         "First certified version"
}
```

| Field | Description |
|-------|-------------|
| `sha256_hash` | Unique fingerprint of the file's exact byte content |
| `timestamp_utc` | Local generation time (not blockchain-anchored unless you run `ots stamp`) |
| `previous_hash` | SHA-256 of the previous CDM file — creates tamper-evident chain |
| `previous_hash: null` | First version in the chain |

> **Optional — anchor to Bitcoin blockchain (free):**  
> `pip install opentimestamps-client`  
> `ots stamp artwork.blend.cdm.json`  
> This creates `artwork.blend.cdm.json.ots` — proof the file existed at this exact moment, verified against the Bitcoin chain. No account needed.

## `blender_metadata.py` — Internal Metadata via Custom Properties

**§4.2.2**

Adds a standardised block of Custom Properties to the active Blender scene — the informal "Level 1" internal metadata layer described in §4.2.2. Run it once per project and the metadata is saved inside the `.blend` file permanently.

**Run:** double-click `run_blender_metadata.bat` — Blender si apre con lo script già caricato nel workspace Scripting.  
> `_launch_metadata.py` is an internal helper used by the launcher — ignore it, do not run it directly.  
**Manuale:** Blender → Scripting workspace → Open → `Alt+P`

### Edit the CONFIG block at the top of the script

```python
AUTHOR      = "Gianpiero Moioli"
TITLE       = "Untitled Work"
DATE        = "2025-01-01"
LICENSE     = "CC BY-NC 4.0"      # or "CC0", "CC BY", "All Rights Reserved"
VERSION     = "1.0"
CHAPTER_REF = "Art Between Matter and Code — Chapter 4"
NOTES       = ""
```

### Where to find the properties in Blender

`Properties panel (N) → Scene → Custom Properties`

Or via Python console: `bpy.context.scene["meta_author"]`

> **Why Custom Properties are Level 1 only:**  
> They are informal and editable by anyone — there is no cryptographic binding between the metadata and the file content. Anyone can open the `.blend` and change `meta_author` to any value. For external verifiable certification, always combine with `certify_asset.py`.
